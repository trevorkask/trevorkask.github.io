LECTURE 2: RPC & THREADS

Why Go?
- Good support for threads and synchronization between threads
- Convenient RPC package
- Type safe and memory safe

Concurrency is important coz it is the case that a computer may want to talk to many other computers e.g a client talking to servers or a server serving requests from many clients.

Goroutines are threads. They are not traditional operating system (OS) threads. They are a lightweight abstraction known as "user-space threads" or coroutines. While both enable concurrent execution, goroutines are managed by the Go runtime rather than the OS kernel, allowing you to run millions of them at a fraction of the memory cost.
- Memory Footprint: A standard OS thread typically reserves 1MB to 8MB of memory. A goroutine starts at a tiny 2KB and grows or shrinks dynamically as needed.
- Creation & Switching Cost: Creating an OS thread requires heavy interaction with the OS kernel, making it slow and expensive. Spinning up a goroutine only involves a memory allocation in the Go runtime, making it virtually instant.
- Scheduling: OS threads are managed directly by the kernel via preemption. Goroutines are scheduled by Go's internal scheduler using an M:N model

Each goroutine will send a RPC call

Threads are important for:
- I/O concurrency
- Parallelism

Thread challenges:
- Race conditions - what thread gets there first. Locks also bring their own problems
- Coordination - channels in go help communicate between goroutines. Condition variables - give a kick to a thread waiting for you. Wait groups - launching a known number of coroutines and waiting for them to finish.
- Deadlock
