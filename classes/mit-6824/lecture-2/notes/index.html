Lecture 2: RPC & Threads

Go, goroutines, RPC calls, coordination, and thread hazards.

Why Go?

  • Good support for threads and synchronization between threads.
  • Convenient RPC package.
  • Type safe and memory safe.

Concurrency is important because a computer may want to talk to many other computers, such as a client talking to servers or a server serving requests from many clients.

Goroutines

Goroutines are threads, but they are not traditional operating system threads. They are a lightweight abstraction known as user-space threads or coroutines. Both enable concurrent execution, but goroutines are managed by the Go runtime rather than the OS kernel, allowing you to run millions of them at a fraction of the memory cost.

  • Memory footprint: a standard OS thread typically reserves 1 MB to 8 MB of memory. A goroutine starts at a tiny 2 KB and grows or shrinks dynamically as needed.
  • Creation and switching cost: creating an OS thread requires heavy interaction with the OS kernel, making it slow and expensive. Spinning up a goroutine only involves a memory allocation in the Go runtime, making it virtually instant.
  • Scheduling: OS threads are managed directly by the kernel via preemption. Goroutines are scheduled by Go's internal scheduler using an M:N model.
  • Each goroutine can send an RPC call.

Threads are important for

  • I/O concurrency
  • Parallelism

Thread challenges

  • Race conditions: what thread gets there first. Locks also bring their own problems.
  • Coordination: channels in Go help communicate between goroutines. Condition variables give a kick to a thread waiting for you. Wait groups help launch a known number of coroutines and wait for them to finish.
  • Deadlock
